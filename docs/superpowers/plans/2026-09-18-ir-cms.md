# IR CMS Implementation Plan (CodeIgniter 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a CodeIgniter 4 server-rendered admin CMS so one operator can review SGX-imported announcements, edit summary/email copy, Publish to the website, manage admin digest recipients, and view sync history — with Publish required before Send.

**Architecture:** Extends the CI4 `backend/` app from the SGX Mirror plan. Admin routes under `/admin/*` use CI4 Session (cookie HttpOnly, Secure, SameSite=Strict), one password hash from `.env`, CSRF filter on POST, and `audit_log` / `admin_recipients` / `email_campaigns` migrations. Controllers in `App\Controllers\Admin`, Views in `app/Views/admin`. Send queues one campaign row; the Email plan owns the worker.

**Tech Stack:** CodeIgniter 4.7+, MySQL, CI Session + CSRF + Validation, Spark (optional), PHPUnit Feature tests, View templates.

## Global Constraints

- Depends on Mirror: `announcements`, `sync_runs`, public API.
- Stay inside CI4 — Controllers/Models/Libraries/Views; no parallel plain PHP admin.
- One admin account; `admin.username` + `admin.passwordHash` in `.env` (password_hash).
- Session: HttpOnly, Secure, SameSite=Strict; `session()->regenerate(true)` after login.
- CSRF on all admin POST mutations (`csrf_field()` + CI CSRF filter).
- Publish and Send are separate; Send disabled until `state === published`.
- Source payload read-only; never overwritten by summary edits.
- Escape output via CI esc() / view escaping; do not render SGX/admin HTML raw.
- Audit login, summary edit, publish, send, retry, archive, settings — no secrets in metadata.
- ≤5 admins (shared login OK), ≤20 announcements/month.
- Design: `docs/SGX_MIRROR_EMAIL_ALERTS_CMS_DESIGN_VI.md`.
- Categories bootstrap = frontend `ANNOUNCEMENT_CATEGORIES` until TDC list.
